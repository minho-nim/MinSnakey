# 꼬물 레이스 v0.3

머리·몸통·꼬리를 직접 그리고, 조립한 뱀으로 CPU 3마리와 100m 경주하는 한국어 웹게임. React + TypeScript + Canvas. 로그인·외부 AI·유료 서버 없이 실행된다.

## 실행

Node.js 22 이상 (검증 환경: 24.19.0).

```bash
npm ci
npm run dev
```

개발 주소: http://localhost:5173

설치 없이 플레이하려면 빌드 결과의 `dist/play.html`을 브라우저에서 열면 된다. CSS·JS가 모두 포함된 오프라인 파일이다. 로컬 파일과 웹 호스팅은 브라우저 저장 공간이 서로 다를 수 있다.

```bash
npm run check       # 타입 검사 + 시뮬레이션/데이터 검증 + 프로덕션 빌드
npm run test:e2e    # Chromium에서 실제 UI 흐름 검증
npm run preview    # 빌드한 dist 미리보기
```

브라우저 테스트는 `/usr/bin/chromium`을 기본으로 사용한다. 다른 머신에서는 호환 Chromium 경로를 `CHROMIUM_PATH`로 지정한다. GitHub Pages 등 정적 호스팅에는 `dist/`를 올릴 수 있으나 이 작업에서 운영 배포는 하지 않았다.

## 구현 기능

- 부위별 자유 그리기, 6색 펜·굵기 조절·되돌리기·부분 지우개·샘플 삽입·연결점 이동
- 부위별 원본 벡터 선, 연결점, 크기, 보수적 충돌 경계 저장
- 조립한 뱀의 관절 움직임 미리보기와 이름 지정, 최대 20마리 로컬 보관·수정
- 경기 준비: 출전 선수 4마리, 자동/수동 즉시 전환, 재진입 시 자동으로 초기화
- 고정 간격 120Hz 시뮬레이션, 몸통 관절 길이 제약, 파동 추진·마찰·에너지·속도 상한
- 자동/수동/CPU가 같은 물리 함수를 사용, 체형으로 능력치 계산
- 3초 카운트다운, 실제 거리 기반 횡스크롤·순위·HUD·25m 구간 표시
- 모바일 좌우 추진 버튼, PC A/D·방향키 (좌우 교대 입력, 간격 제한, 입력 중단 시 감속)
- 일시정지·재개·재시작·종료 확인, 탭이 숨겨지면 자동 일시정지, 루프·이벤트 정리
- 결승선 통과 시간 보간, 최종 순위, 최고 속도, 자동/수동·뱀별 개인 최고 기록
- 90초 제한, 미완주 표시, 재경기·그림 수정·메인 복귀
- 손상된 저장 데이터 필터, 저장 실패 알림, 모바일 반응형

## 물리와 그림 표현

`geometry.ts`는 몸통의 가장 긴 실제 펜 경로를 호 길이로 샘플링해 25개 관절을 만든다. 그린 굴곡은 휴식 상태의 골격에 그대로 남는다. 원본 점은 가까운 선분의 접선·법선 좌표에 바인딩한다. 정지 상태에서는 고리와 불규칙한 선도 수치 오차 이내로 원래 좌표가 복원된다. 몸통과 머리·꼬리에 같은 축척을 사용하므로 부위 크기를 고정된 공통 크기로 바꾸지 않는다.

`model.ts`는 경로 길이·굴곡·펜 두께와 전체 잉크 면적에서 길이·유연성·무게·능력치를 계산한다. `physics.ts`는 1/120초 간격으로 원래 골격의 국소 법선 방향에 파동을 가하고, 개별 관절 길이 제약과 접촉 일·마찰·질량·지구력·속도 상한을 적용한다. `render.ts`는 원본 stroke 점을 움직이는 관절에 맞춰 변형하고 머리·꼬리를 연결한다. 경기와 미리보기는 같은 골격과 렌더러를 사용한다. 독립 레인이므로 선수 간 충돌은 없다.

v0.2는 첫 진입부터 그리기 종이가 열리는 게임 화면이다. 큰 종이, 굵은 조작 버튼, 단계별 머리·몸통·꼬리, 실시간 길이·무게·유연성 정보, 부분 지우개, 연결점 이동, 조립 미리보기를 제공한다. 원본 그림과 저장 스키마는 유지한다.

이는 안정적인 캐주얼 게임을 위한 간소화 모델이다. 완전한 강체 충돌 엔진·실제 생체역학·임의 면의 정밀 윤곽/중심선 추출은 구현하지 않았다. 저장된 충돌 경계는 추후 코스 구현용 데이터이며 현재는 장애물 충돌에 사용하지 않는다. 체형과 입력이 같은 경우 결과는 결정적이며 우승자를 사전 지정하지 않는다.

## 파일 구조

- `src/App.tsx`: 화면 흐름, 그리기, 경기 UI
- `src/model.ts`: 그림·뱀 데이터와 형태 분석
- `src/geometry.ts`: 원본 경로 골격·스키닝·부분 지우개
- `src/Workshop.tsx`: 게임형 그리기 화면·실시간 정보·연결점 편집
- `src/physics.ts`: 순수 시뮬레이션, CPU 자동 추진, 수동 입력, 순위
- `src/render.ts`: Canvas 손그림 스키닝·트랙·카메라
- `src/storage.ts`: 브라우저 저장·검증·최고 기록
- `tests/physics.test.ts`: 엔진·입력·저장 데이터 검증 16개
- `tests/browser/game.spec.ts`: PC·모바일 UI 자동화 7개
- `docs/SPEC.md`: 원본 개발 지시서
- `docs/AI-OFFICE.md`: 이후 AI Office 연결 방법
- `AGENTS.md`, `scripts/setup.sh`: 다음 개발 에이전트의 작업 규칙과 설치

## 검증 결과

- `npm run check`: 성공, 타입 검사·테스트 16개·빌드 통과
- Chromium 자동화 7개: 성공
- 직접 그린 3부위 조립 → 이름 저장 → 자동/수동 전환 → 카운트다운 → 일시정지/재개 → 100m 완주 → 결과 → 새로고침 후 보관 확인
- 390×844 모바일: 가로 넘침 없음, 수동 추진·재시작·종료·자동 모드 복귀 확인
- 1440×1000 PC: 가로 넘침 없음, 홈·준비 화면 캡처 확인
- 시뮬레이션: 모든 CPU/자동 완주, 30/120fps 결과 일치, 관절 간 거리 유지, 연타 제한, 수동 무입력 감속 및 제한시간 확인
- 브라우저 런타임 오류 0건
- 단일 HTML 빌드도 로컬 HTTP로 실행해 완주 확인, 외부 요청 0건. 관리형 Chromium의 정책으로 file:// 직접 열기는 검증하지 못했다.

스크린샷은 `docs/*-desktop.png`, `docs/*-mobile.png`에 저장했다. 실제 iOS/Android 하드웨어, Safari, 장시간 메모리 프로파일, OS 가상 키보드 동작은 아직 검증하지 않았다.

## 남은 기능과 다음 단계

- 코스 달리기·경사·물웅덩이·장애물은 미구현이며 준비 화면에서 비활성화했다.
- 머리·꼬리는 기본 연결점을 사용하며, 각 부위의 연결점을 종이 위에서 직접 지정할 수 있다. 몸통은 첫 번째(머리 쪽) 연결점만 직접 지정한다.
- 몸통의 가장 긴 펜 선을 골격으로 사용한다. 여러 분리된 선을 그리면 다른 선들은 가까운 골격에 묶인다. 복잡한 가지·면의 진짜 중앙선을 자동 추출하는 엔진은 아니다.
- 기록과 그림은 이 브라우저에만 저장된다. JSON 내보내기/가져오기·삭제 UI·기기 간 동기화는 추후 작업이다.
- 수동·자동의 기본 추진 상한은 같지만 다양한 사용자 리듬을 대상으로 한 플레이 밸런스 조정은 추가로 필요하다.
- GitHub 저장소: https://github.com/minho-nim/snake-race . 전용 저장 클라우드 환경과 AI Office 작업 전달 연동은 아직 미설정이다. 이 게임은 현재 채팅의 클라우드 작업 공간에서 개발했다.

다음 개선 우선순위: 실제 휴대폰 터치 플레이 검증, 폐곡선 몸통의 면 중앙선 추출, 반복 플레이를 통한 체형 밸런스 조정.

## GitHub Pages 자동 배포 준비

`.github/workflows/pages.yml`에 main 업데이트 시 검사·빌드·공개 배포하는 절차를 준비했다. 저장소는 생성됐으며 Pages의 Source를 GitHub Actions로 선택하는 최초 설정이 필요하다. 자세한 절차는 `docs/GITHUB-PAGES.md`에 있다. GitHub Pages 배포 성공 여부는 저장소 Actions 실행 결과에서 확인한다.

## v0.3 경기 진행 개선

- 기본 재생 속도 1.5배, 빨리감기 버튼으로 1.5 → 3 → 6배 순환. 물리 시간과 기록은 동일하며 관전 시간만 단축한다. 카운트다운은 실제 3초로 유지한다.
- 결과보기는 현재 물리 상태에서 나머지 경기를 계산한다. 수동 모드에는 추가 조작을 만들지 않으므로 미완주할 수 있다. 완주 기록이 없으면 개인 최고 기록에 저장하지 않는다.
- 경기 배율은 원래 체형과 파동 여유 공간으로 경기 시작 때 계산해 고정하고, 창 크기가 바뀔 때만 갱신한다. 꿈틀거림에 따른 확대·축소를 제거했다.
