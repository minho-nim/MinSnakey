# 게임 플레이 기록 정리

> **minoffia 메모:** Donchitos/Claude-Code-Game-Studios@abc0de7 `playtest-report`(MIT, LICENSE 같이 둠)의 틀과 분류 방법을 한국어로 새로 썼다. 원문은 그 저장소 전용 스크립트·문서에 기대고 있어 그대로 옮기지 않았다.

## 지시서용 요약

- 소유자 메모·업무 설명·game-qa 봇 플레이 결과를 아래 틀에 채운다. 없는 칸은 "기록 없음"으로 두고 지어내지 않는다.
- 부서지는 것(멈춤·진행 불가·프레임 급락)은 "막힌 곳"이 아니라 **버그** 표에 넣는다. 막힌 곳은 "하는 느낌"의 문제만.
- 끝에 고칠 것을 네 갈래로 나누고, 가장 중요한 3가지를 고른다. 규칙·수치를 바꾸는 것은 game-design·game-balance로 넘긴다.
- 저장소에 남길 때는 `docs/playtests/YYYY-MM-DD.md`.

## 틀

```markdown
# 플레이 기록 YYYY-MM-DD
- 버전/커밋:  · 기기: 휴대폰/PC · 조작: 터치/키보드 · 한 판 길이:
## 무엇을 보려고 했나
## 첫인상(처음 1분)
- 목표를 알았나: 예/아니요/조금 · 조작을 알았나: 예/아니요/조금 · 느낌: 재밌음/헷갈림/지루함/답답함
## 잘 된 점
## 막힌 곳(느낌) — 심각도 높음/중간/낮음
## 헷갈린 곳과 이유
## 좋았던 순간
## 버그
| # | 내용 | 심각도 | 다시 되나 |
## 숫자(있으면): 죽은 횟수·위치, 구간별 시간, 최고 점수
## 전체: 또 할까(예/아니요/글쎄) · 난이도(쉬움/적당/어려움) · 속도(느림/적당/빠름)
## 다음에 고칠 3가지
```

## 고칠 것 나누기

| 갈래 | 넣는 것 | 넘길 곳 |
| --- | --- | --- |
| 기획 | 재미·규칙·헷갈림 | game-design |
| 밸런스 | 숫자가 이상함, 난이도 튐 | game-balance |
| 버그 | 다시 되는 고장 | debugging-and-error-recovery·game-debug |
| 다듬기 | 막지는 않는 불편·손맛 | game-ui·emil-design-eng |
