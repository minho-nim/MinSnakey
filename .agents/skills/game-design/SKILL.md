# 게임 기획

> **minoffia 메모:** 미노피아가 만든 스킬. 『게임 기획 실무에서 바로 쓰는 AI·클로드 코드 활용법』(eremes81/game-design-ai-practice, 이민수·조지희, CC BY-NC-SA 4.0)의 방법(수치 먼저, 문서를 작은 단위로, 결정 기록과 영향 추적, 시뮬레이션으로 밸런스 확인)을 참고해 작은 웹 게임에 맞게 새로 썼다. 책의 글은 옮기지 않았다.

## 지시서용 요약

- 코드를 고치기 전에 `docs/game-design.md`(없으면 만듦)에서 바꿀 곳을 먼저 고친다. 기획과 코드가 다르면 기획을 고칠지 코드를 고칠지 소유자에게 묻는다.
- 숫자(속도·점수·확률·시간)는 코드 곳곳에 흩지 말고 한 파일(`src/config` 등)의 표로 모은다. 숫자마다 "왜 이 값인지"를 한 줄 주석으로.
- 지어낸 숫자를 쓰지 않는다. 근거가 없으면 "추정"이라고 적고, 시험이나 간단한 시뮬레이션으로 확인한 뒤 고친다.
- 규칙을 바꾸면 결정 기록에 한 줄(날짜·무엇을·왜·영향 받는 곳)을 남기고, 영향 받는 곳(점수판·튜토리얼·저장 데이터·시험)을 찾아 같이 고친다.

## 1. 한 장짜리 기획서(먼저 이것부터)

`docs/game-design.md`에 아래 순서로, 각 칸 1~3줄.

| 칸 | 쓰는 것 |
| --- | --- |
| 핵심 재미 | "○○할 때 △△해서 재밌다" 한 줄. 이 줄에 안 맞는 기능은 뺀다 |
| 핵심 반복 | 한 판 안에서 되풀이하는 행동: 보기 → 고르기 → 결과 → 보상 |
| 조작 | 키보드·마우스·터치 각각. 휴대폰 한 손으로 되는지 |
| 이김·짐 | 끝나는 조건, 다시 하기까지 걸리는 시간(짧을수록 좋음) |
| 점수·성장 | 무엇을 하면 점수가 오르나, 최고 기록을 어떻게 남기나 |
| 난이도 곡선 | 처음 30초·3분·10분에 무엇이 달라지나 |
| 하지 않을 것 | 이번 판에서 일부러 안 하는 것(범위를 지키려고) |

## 2. 수치 표

- 수치는 한 표에: 이름 · 값 · 단위 · 근거(시험·계산·추정) · 바뀐 날짜.
- 서로 엮인 수치(예: 속도 × 시간 = 거리, 점수 증가 속도 × 평균 생존 시간 = 평균 점수)는 식으로 적고, 한 값을 바꾸면 엮인 값도 다시 계산한다.
- 밸런스는 감이 아니라 확인: 작은 스크립트로 여러 판을 흉내 내(시드 고정) 평균·최소·최대를 본다. 예: 평균 생존 시간, 첫 판 실패율, 최고 점수 분포.

## 3. 결정 기록과 영향 추적

`docs/game-design.md` 맨 아래 "결정 기록"에 최신이 위로:

```
- 2026-11-17 · 점수 10m마다 효과 · 왜: 진행감 부족 · 영향: Hud, render, 시험 score-pop
```

규칙·수치를 바꿀 때는 그 이름으로 저장소를 검색(grep)해 쓰는 곳을 모두 찾고, 결정 기록의 "영향"에 적은 곳과 맞는지 확인한다. 빠진 곳이 있으면 같이 고친다.

## 4. 정합성 점검(끝내기 전에)

- 기획서의 숫자와 코드의 숫자가 같은가.
- 튜토리얼·도움말·점수판 문구가 바뀐 규칙과 맞는가.
- 저장 데이터(최고 기록 등) 형식이 바뀌었으면 예전 기록을 읽을 수 있는가.
- 이김·짐·다시 하기 흐름이 끝까지 되는가(game-qa로 실제로 돌려 본다).

## 5. 출시 뒤 볼 것(있으면)

한 판 길이, 다시 하기 비율, 첫 판에서 그만두는 비율, 최고 점수 분포. 숫자가 없으면 지어내지 말고 "아직 없음"이라고 적는다.
