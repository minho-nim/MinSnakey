# 게임 밸런스 확인

> **minoffia 메모:** Donchitos/Claude-Code-Game-Studios@abc0de7 `balance-check`(MIT, LICENSE 같이 둠)의 방법(자료 없으면 "확인 못 함", 목표 범위와 비교, 영역별 점검, 표로 보고)을 작은 웹 게임에 맞게 한국어로 새로 썼다. 원문은 그 저장소 전용 스크립트·문서에 기대고 있어 그대로 옮기지 않았다.

## 지시서용 요약

- 먼저 자료가 있는지 본다: 수치 파일(`src/config` 등)·기획서(`docs/game-design.md`의 수치 표)·시험/시뮬레이션 결과. 각각 "있음/없음"으로 적는다.
- 목표 범위가 없는 값은 판단하지 않는다("범위 없음 — 판단 안 함"). 자료가 아예 없으면 보고 전체가 **확인 못 함**이고, 그게 맞는 답이다. 초록불을 지어내지 않는다.
- 숫자를 바꾸면 game-design의 수치 표·결정 기록도 같이 고친다.

## 1. 무엇을 볼지 정하기

| 영역 | 보는 것 |
| --- | --- |
| 난이도 | 시간·단계에 따라 속도·적·장애물이 어떻게 늘어나나, 갑자기 튀는 구간·너무 밋밋한 구간 |
| 점수 | 점수가 오르는 속도, 끝없이 불어나는 곳(무한 콤보·반복 이득), 최고 기록이 말이 되는 범위인가 |
| 보상·아이템 | 늘 고르는 것 하나만 이기나(다른 선택이 쓸모없나), 확률·나오는 간격 |
| 진행 | 처음 30초 안에 규칙을 알 수 있나, 한 판 길이, 다시 하기까지 시간 |

## 2. 확인하는 방법(규칙 먼저, 감은 나중)

1. 수치 표의 각 값을 목표 범위와 비교한다. 벗어나면 "튀는 값" 표에 한 줄.
2. 엮인 값은 식으로 계산한다(예: 점수 증가 속도 × 평균 생존 시간 = 평균 점수).
3. 가능하면 작은 시뮬레이션: 시드를 고정하고 봇이 여러 판(예: 200판)을 돌려 평균·최소·최대를 본다. 결과를 숫자 그대로 적는다.
4. 사람 플레이 기록이 있으면(game-playtest) 숫자와 느낌이 맞는지 견준다.

## 3. 보고 형식

```
## 밸런스 확인: <시스템>
읽은 자료: <파일 목록, 없으면 없음>
상태: 확인 못 함 / 괜찮음 / 걱정 있음 / 심각
### 튀는 값
| 값 | 목표 범위 | 실제 | 문제 |
### 늘 이기는 전략
- <무엇이 왜 문제인가>
### 진행 곡선
<표나 한 줄 설명>
### 고칠 것(작은 것부터)
1. <값> <지금> → <제안> · 근거
```
